# Git hooks — gotchas

## Tracked hook dirs (husky / `.githooks`) only run if `core.hooksPath` is set

Shipping `.husky/` or `.githooks/` in a repo does **nothing** on its own. Git
runs `$GIT_DIR/hooks` unless `core.hooksPath` points elsewhere. husky sets it
via `npm install` (its `prepare` script); plain tracked dirs need
`git config core.hooksPath .githooks` run manually. A fresh clone has neither
until the repo's setup runs — so the shipped hooks are silently inactive. Verify
with `git config --get core.hooksPath`, not by checking the dir exists.

## `pre-commit` framework hooks aren't armed by cloning either

`.pre-commit-config.yaml` only enforces after `pre-commit install` writes
`.git/hooks/pre-commit` in that clone. Never committed, per-clone. A
misformatted commit sails through locally and fails at CI. `init.templateDir` +
`pre-commit init-templatedir` arms *future* clones only — misses anything
checked out before the template was set (the container gap).

## `git config --global init.templateDir` arms future clones, never existing ones

Setting the template dir copies its `hooks/` into repos cloned/`init`'d
*afterward*. Existing repos are untouched — you need an explicit sweep
(`dotagents arm-hooks`) to retrofit them.

## `git init` copies template hooks — isolate tests with an empty template

When testing hook-installation sweeps, `git init` silently copies
`init.templateDir`'s hooks into the new repo, contaminating assertions about
what the sweep installed. Init test repos with `git init --template="$(mktemp -d)"`
(an empty dir) to start from a clean `.git/hooks`. The empty template also means
no `.git/hooks/` dir is created — `mkdir -p` it before writing a hook there.

## Replacing a pre-commit hook safely: detect by marker, dedupe by content

To decide whether `.git/hooks/pre-commit` is safe to overwrite: a pre-commit-
generated hook contains `File generated by pre-commit`; our guard contains
`dotagents-hook-guard`. Anything else is a foreign/maintainer hook — leave it.
For idempotency use `cmp -s new old` (skip if byte-identical) rather than mere
presence, so a stale version still self-updates.

## pre-commit's generated hook hardcodes an interpreter path — don't copy it

The generated `.git/hooks/pre-commit` bakes in
`INSTALL_PYTHON=/Users/.../uv/tools/pre-commit/bin/python`. That path is
machine-specific and breaks in containers/other machines. A portable hook should
`exec pre-commit hook-impl …` guarded by `command -v pre-commit` only.
