# Limitations

Known edge cases left unfixed: what, where, the guard if any, what would make it matter, and its issue.

- The pkill/killall guard (`home/.claude/hooks/omnigent-only.py`, from #83) misses a wrapper option that takes a value (`sudo -u bob pkill -f gate`), the existing wrapper-parser ceiling, and trusts any pattern with a `/` or an 8+ character letter-and-digit token as the session's own. No guard. Matters if an agent adds `sudo -u` to a kill or uses a shared path. #83.
- The host command rules (`~/.agents/host-commands`, read by `omnigent-only.py`) match a command's leading words only, after the launchers `swiftly run`, `uv run`, `python` and `python3` and with a path word counted by its basename, so a rule is skipped when a wrapper option takes a value (`sudo -u bob swift build`), when a wrapper script runs the toolchain, and when a launcher carries its own options (`uv run --with x approvals.py local-ci`). No guard. Matters if an agent routes a forbidden build through such a wrapper. #168.
- The sleep-loop guard (`omnigent-only.py`) reads only the command line, so a `while`/`until` loop in a script the command runs (`./poll.sh`) or in another language (`python -c 'while ...: time.sleep(5)'`) passes. No guard. Matters if an agent moves its hand-written wait into a script to get past the hook. #170.
- An LFS repo whose `.pre-commit-config.yaml` opts into `post-checkout` keeps the template guard, so git-lfs's lock hooks (`post-checkout`, `post-commit`, `post-merge`) are not installed in its clones (`lib/postcheckout-guard.sh`, the `ponytail:` line). No guard; `git lfs update` says so. Matters if a repo uses both LFS file locking and a pre-commit post-checkout hook. #68.
- `skill_requirements` (`bin/dotagents`, the `ponytail:` line) reads `metadata.requires` line by line, so a flow mapping (`metadata: {requires: ..}`) is missed, and it takes each declared name as both the command and its mise tool. No guard. Matters if a skill writes its frontmatter in flow style or needs a tool whose mise name differs from its command. #97.
- The doctor's stale-copy scan (`check_stale_skill_copies` in `bin/dotagents`) prunes every directory named `tmp`, `.tmp`, `.cache`, `workspaces` or `runs`, so a project checked out below one (`~/tmp/proj/.claude/skills`, `~/dev/workspaces/proj/.claude/skills`) is not scanned. No guard. Matters if agents are run in projects under such a directory. #103, #175.
- `claude-code-mode` (and the code-mode plugin it turns on) needs `bun`, which install doesn't provide. The launcher stops with a message naming bun; there is no other guard. Matters on a machine without bun (a VPS or remote container); fix by declaring bun as a required tool. #108.
